# Getting help

Push to GitHub is a free, open-source project with one volunteer maintainer.
Support is best effort: there is no guaranteed response time, but every issue
is read.

## Before asking

1. In the dialog, click **Check My Setup…**. It finds most problems and says
   what to do.
2. Look up the message in the [troubleshooting guide](docs/TROUBLESHOOTING.md).
3. Search the [existing issues](https://github.com/zcohen-nerd/FusionToGitHub/issues?q=is%3Aissue).

## Asking a question or reporting a bug

Open an [issue](https://github.com/zcohen-nerd/FusionToGitHub/issues/new/choose)
and pick **Bug report** or **Feature request**. Please include:

- the add-in version (the summary, or the log's "Add-In Loaded and running" line);
- your Fusion version (**Help → About**) and operating system;
- your Git version (**Check My Setup…** shows it);
- what you did, what you expected, and what happened, including the full
  message (with its *Technical details*);
- the relevant part of the log (**Help & Privacy → Open Log File…**).

**Remove private information first.** The log never contains passwords or
tokens, but it does contain folder paths, repository addresses and design
names. Never paste a token anywhere; if one is exposed, revoke it on GitHub
straight away.

## Security problems

Please don't describe a security problem in a public issue. Follow
[SECURITY.md → Reporting a problem](SECURITY.md#reporting-a-problem).
